1. API reachable from the network and from any website HIGH

  • apps/api/src/main.ts:39 — app.listen(port) has no host, so it binds every interface. Anyone on the same LAN / Wi-Fi can use the API; there is no auth.
  • apps/api/src/main.ts:35 — enableCors({ origin: true }) reflects any origin. Any page open in the browser can read /api/accounts/:id/transactions.
  • Even without CORS, a malicious page can send a multipart POST /api/imports (a "simple" request, no preflight), and PATCH / DELETE once CORS allows it — cross-site request forgery.

Fix direction: app.listen(port, '127.0.0.1'); limit CORS to http://localhost:5173 or drop it (the Vite proxy makes it unnecessary).

2. Upload size and type (apps/api/src/import/import.controller.ts)

2a. File size OK

FileInterceptor sets limits: { fileSize: MAX_BYTES } (10 MB); multer rejects larger files with 413. The manual check at line 48 is unreachable but harmless.

2b. Missing multer limits LOW

No fields, fieldSize, parts, files. Multer defaults allow unlimited non-file fields at up to 1 MB each — a memory-exhaustion vector, reachable only because of #1.

2c. Client-trusted content type LOW

file.mimetype is whatever the client sends. Not a security hole — the parser rejects anything without a Sparkasse header (HEADER_NOT_FOUND → 400). But real CSVs sent as text/plain, application/octet-stream or with an empty type are wrongly rejected. Extension is not checked.

3. Malformed CSV handling

WORKS

  • Invalid UTF-8 falls back to Windows-1252 (cannot throw) — decode.ts.
  • Structural errors (CSV_*) and CsvFileError return 400 — import.service.ts:240-261.
  • A bad row is reported; other rows still import.
  • Amounts checked as safe integers; dates validated incl. leap years — fields.ts.
  • Binary junk → no header → 400.
  • No SQL injection: Prisma queries parameterized, no $queryRaw / $executeRaw.

3a. Error output uncapped LOW

RowError.value holds the full raw bad value. import.service.ts:136-138 logs one line per error, and the response returns all of them. A 10 MB file of bad rows (or one huge field) floods the log and bloats the response. Fix: cap error count, truncate value.

3b. Log injection LOW

import.service.ts:125 logs file="${request.fileName}"; :356 logs value="…". Both unescaped. originalname and cell values can contain CR/LF or ANSI escape codes → forged log lines. Fix: escape control characters before logging.

4. Path handling NOTHING FOUND

  • Uploads stay in memory (no multer dest). originalname is only stored and displayed; React escapes it; no dangerouslySetInnerHTML anywhere.
  • mkdirSync in prisma.service.ts:18 uses only DATABASE_URL (trusted config).
  • rmSync in scripts/reset-e2e-db.mjs and apps/api/src/test/global-setup.ts delete fixed paths only.
